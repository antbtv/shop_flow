# ADR-0003: Сетевая модель Pi5: как не открыть порты наружу

- **Статус:** принято (2026-09-25)
- **Контекст:** PRD 6.1 требует, чтобы ClickHouse (8123, 9000) и Airflow (8080) были доступны с ноутбука, но не снаружи домашней сети. Сервисы работают в Docker. Docker публикует порты через DNAT и цепочку FORWARD, поэтому правила ufw в цепочке INPUT на опубликованные порты контейнеров не действуют.
- **Решение:**
  - Порты контейнеров публикуются только на LAN-адрес Pi5 через переменную: `"${PI5_HOST}:8123:8123"`. Никаких `0.0.0.0` и `[::]`.
  - ufw (`default deny incoming`) защищает службы самого хоста; снаружи разрешён только SSH (22) из LAN-подсети.
  - Защита в глубину: правило в цепочке `DOCKER-USER` (через `/etc/ufw/after.rules`) отбрасывает трафик к контейнерам не из LAN-подсети.
  - IPv6: если у Pi5 есть глобальный адрес, ufw с `IPV6=yes` и запрет входящего IPv6 на роутере.
  - Bind на конкретный IP не должен падать при загрузке, если сеть поднялась позже Docker: `net.ipv4.ip_nonlocal_bind=1` или ожидание `network-online.target`. Выбор фиксируется в 0.8 по факту менеджера сети на Pi5.
- **Рассмотренные варианты:**
  - Только ufw: не работает для Docker, ложное чувство защищённости.
  - Bind на LAN-IP (выбрано): простое, проверяемое через `ss -tlnp`.
  - Tailscale/WireGuard: стабильные имена и доступ вне дома, но лишний сервис и внешняя зависимость. Вернуться, если понадобится доступ вне домашней сети.
- **Приёмка:** `sudo ss -tlnp` показывает порты 8123/9000/8080 только на `$PI5_HOST`; тестовый сервис на хосте (`python3 -m http.server 5000`) недоступен с ноутбука; после `reboot` контейнер с `--restart unless-stopped` снова отвечает на `$PI5_HOST`.
- **Последствия:** реальные IP в репозиторий не попадают, только через `.env`. При смене IP Pi5 меняется `.env`, а не compose.
- **История для интервью:** «Docker обходит ufw» — частая ошибка при self-hosting; решение через bind и `DOCKER-USER` вместо надежды на файрвол хоста.
- **Проверено (2026-09-25, Milestone 0.8):** все пункты приёмки пройдены. Глобального IPv6 у Pi5 нет. Защита bind при загрузке не понадобилась: `NetworkManager-wait-online` включён, Docker ждёт `network-online.target`, контейнер на `192.168.0.151` поднимается после reboot. На роутере нет проброса портов и UPnP-пробросов.
